## 1. 已完成且成立的成果

### 1.1 隐藏录制格式持久化 ✅（项目主线，已交付）

| 项 | 内容 |
|---|---|
| 成果 | 把 **NTSC + MOV + `mov_60p_150mbps_c4k`** 持久化写入相机（`0x5e=0x06`、vq `0x92`），**断电重启后仍生效** |
| 手段 | 经 Wi-Fi `cam.cgi` 读写 65,533 B 的 `camsetting` 块；写入必须用**分块 `separate` 协议** |
| 关键坑 | 单次 65 KB POST **永远不会提交**；必须 `startsenddata → 分块 requestsenddata` |
| 金标备份 | `blob_GOLD_mov_persisted_20261013_020600.bin`（sha256 `13b5925…745c`） |

### 1.2 服务模式 / ROM BACKUP ✅（本轮打通）

| # | 结论 | 证据 |
|---|---|---|
| 1 | **进入服务模式**：`回放 + AF ON + 方向右` 开机 | 实机 |
| 2 | **ROM BACKUP 门控 = 卡槽 1 + FAT32 卡**（exFAT 卡会整体变灰；**不需要**"解除初始设置"） | 实机 |
| 3 | **导出成功**：`S5A.TXT`/`S5F.TXT`/`S5U.TXT` = EEPROM 三区（`ADJUST`/`FIX`/`UPDATE`），各 **128 KB**，**纯 ASCII 十六进制** | 实机 |
| 4 | **EEPROM 内无密钥、无固件**（细粒度熵扫描 0 命中；无 AES/证书标记） | 实证 |
| 5 | **身份字段偏移**：`ADJUST 0x0000`=序列号 `XJL2104270015`；`0x20/0x40/0x60`=生产码 | 实证 |
| 6 | **本机是 `GK` 机型（中文区 = PAL）** —— 前期 NTSC 成果是在 **PAL 机型**上实现的 | 实机（INITIAL SETTINGS 界面） |
| 7 | **退出/复位组合键**：`MENU/SET + 方向右` 关机 → 进入 INITIAL SETTINGS → 再按一次完成重置。**⚠️ 必须先拔掉 ROM BACKUP 卡（槽1/FAT32）否则不生效** | 实机 |
| 8 | **EEPROM 读-改-写通道**：格式是**可编辑文本** + 相机原生支持写回（`SD*→DSC`） | 协议分析 |

> ⚠️ **禁令**：在 `INITIAL SETTINGS` 界面**不要按 `DISP.`** —— 会解除 `[Strict]`，
> 使地区后缀变成**可改（仅一次机会、不可逆）**。

### 1.3 PTP 固件更新协议审计 ✅（本轮完成）

| # | 结论 |
|---|---|
| 1 | **协议链路**：`0x9605` 相机给出 `{Status, Address, Size}` → `0x9606` 回送 `[Size][Addr][DataType]` → `0x9607` 传 500 KiB 分块 |
| 2 | **`0x9606` 负载布局**：32 位 12 字节 / 64 位 16 字节（完整还原） |
| 3 | **地址来自相机**（Tether 内是硬编码全局 `0x49e730`/`0x49e744`，客户端协议上可覆盖） |
| 4 | **`0x9406` 8 个子码全部定位**，新增 **`0x00090013` FWUP Request**、**`0x00090014` UPDATE** |
| 5 | **完整 FWUP 状态机**：READY → Request → DATA_TRANSFER → UPDATE → cmp |
| 6 | **空闲态实测**：`0x41000013/14` 返回 `0x2001` + 12 字节全零（无地址） |
| 7 | **USB PID 语义**：`0x2382`=正常 PTP / `0x2370`=服务模式；PTP 须走 **ImageCaptureCore**（原始 USB 被 `ptpcamerad` 独占） |
| 8 | **USB 设备签名含序列号**，与 EEPROM `ADJUST 0x0000` **交叉一致** |

## 2. **已撤回**的结论（重要）

| 结论 | 状态 | 撤回依据 |
|---|---|---|
| "S5 内核越界写已实机确认" | ❌ **撤回** | 注入**必为 NULL** 的 slab 填充区索引（120）→ **只报错不崩** ⇒ 存在 `if (vol_amap[i]==NULL) return -EIO` ⇒ 原推理"报卡写失败 ⇒ 内存写已执行"**不成立** |
| "堆喷命中越界槽" | ❌ **撤回** | A/B 对照：**去掉注入后照样重启** ⇒ 崩溃不能归因于注入 |
| "长名崩溃 = 数量 × 长度" | ⚠️ **修正** | 初版实验里**我们自己的工具把目录链拐进了照片数据区**；重做后结论为 **"长文件名本身"** |

> **方法论教训**：
> **① 没有对照组的结论不要写进报告。**
> **② "相机报写入错误"不能当作"内存写已执行"的判据**（NULL 提前返回表现一样）。
> **（S1R2 报告也用了这个判据，后人不应照抄。）**

## 3. 其他确认结论

### 3.1 exFAT 一线

| # | 结论 | 强度 |
|---|---|---|
| 1 | **内核对簇号不做归属校验**，释放路径**完全跟随卡上被篡改的 FAT 链值** | ✅ 位图实机证据 |
| 2 | **越界索引处存在 NULL 检查、会提前返回** | ✅ 决定性实验 |
| 3 | **360 个 240 字符长名目录项 → 相机开机反复重启**（纯目录项即可触发） | ✅ 四组对照矩阵 |
| 4 | 触发变量 = **长文件名本身**（排除数量/体量/entry-set 分配大小） | ✅ |
| 5 | 阈值在 **58–86 KB**（很像"定长缓冲 + 长度未校验"） | ◐ 推断 |

### 3.2 相机崩溃定因（四组对照矩阵）

| 组 | 文件数 | 名字长度 | entry set | 条目数 | 体量 | 相机 |
|---|---|---|---|---|---|---|
| A | 241 | 240 | 576 B | 2169 | 139 KB | ✅ |
| **B** | **360** | **240** | 576 B | 6480 | 202 KB | ❌ **反复重启** |
| C | 2160 | 12 | 96 B | 6480 | 202 KB | ✅ |
| **D** | **360** | **12**（`num_ext=17`） | **576 B** | 6480 | 202 KB | ✅ |

### 3.3 安全面（Wi-Fi / BLE）

| # | 结论 |
|---|---|
| 1 | **Wi-Fi 控制面有独立授权门**（BLE 注册的身份**不能**打开它） |
| 2 | **BLE 凭据面无认证**：先写身份再读，可读出 **SSID 与 Wi-Fi 密码**（实测密码为空） |
| 3 | **accctrl 只有裸 `ok` 才算授权**；`ok_under_research` **不是** |
| 4 | Wi-Fi 调试后门：**70+ 候选 mode 全部 `err_param`** ⇒ 无后门 |
