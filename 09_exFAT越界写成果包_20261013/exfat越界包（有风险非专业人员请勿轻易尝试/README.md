## ⚠️ 三条最重要的教训（写给下一个复现的人）

1. **Boot Checksum 覆盖 11 个扇区，不是 512 字节。**
   S1R2 报告只写了"跳过 106/107/112"、没写覆盖范围 —— 照字面理解会算错校验和，
   相机会直接判"卡不可用"。我们已在**两种独立实现**上验证了正确算法。

2. **写卡之后必须 `fsync`，回读要用新的文件描述符。**
   块设备写入会停在页缓存里，拔卡就丢 —— 这是前几轮"补丁没生效"的真凶。

3. **一定要有"对照组"。**
   我们曾把"相机反复重启"当成堆喷成功的信号，后来 A/B 对照发现
   **去掉注入后照样重启** —— 崩溃另有原因。**没有对照组的结论不要写进报告。**

## 复现入口（单条命令）

```bash
# 越界注入（自动挑照片 + 写入越界值 524290）
sudo bash 02_工具链/exfat/s5_exfat_test.sh go2 /dev/diskNsM

# 回到 Mac 后核对现场 + 自动裁决
sudo bash 02_工具链/exfat/s5_exfat_test.sh verdict /dev/diskNsM
```

> macOS 的**原始磁盘设备同时受 Unix 权限与 TCC 保护**，
> 自动化/AI 进程通常两者都过不去 —— **这些命令必须由人在终端里用 sudo 执行**。
