# DC-S5 exFAT 内核越界写 —— 成果总结（全文）

2026-10-13 · 起点是 S1R2 团队的阶段报告，终点是**在 DC-S5 实机上确认了内核越界写原语**。

---

## 0. 一句话

> 用一张**只改 4 字节 FAT** 的自制 SD 卡 + 相机自带的"删除照片"操作，
> 让 DC-S5 的内核**在自己的内存里执行了一次越界位清除写** ——
> **不拆机、不接 UART/JTAG、不改固件、不写一行代码进相机。**

---

## 1. 起点：S1R2 报告给了什么

S1R2 团队（Socionext SC2006A，4×A53，Linux 4.19）发现：相机把三星 sdFAT 的
staging 版 exFAT 驱动原样搬入，而**没有跟进上游补丁**，导致：

```c
/* drivers/staging/exfat/exfat_core.c */
539: map_size   = (u32)GET64_A(ep->size);                       /* 来自卡上的位图 DataLength */
541: map_sectors = ((map_size - 1) >> sector_size_bits) + 1;
543: vol_amap   = kmalloc_array(map_sectors, sizeof(struct buffer_head *), GFP_KERNEL);

592: s32 set_alloc_bitmap(struct super_block *sb, u32 clu) {
599:     i = clu >> (p_bd->sector_size_bits + 3);                /* ← 只用簇号算索引 */
604:     exfat_bitmap_set((u8 *)p_fs->vol_amap[i]->b_data, b);   /* ← 越界索引后写入 */
     }
```

- `map_sectors` 来自**卡上的位图长度**，而索引来自**簇号**，**两者之间没有任何一致性校验**
- 所有位图入口都**没有 `is_valid_cluster()`**
- 上游重写版（`fs/exfat/balloc.c`）有 `need_map_size` 与 `is_valid_cluster()`，厂商一条都没有

**攻击链**：改 FAT 链尾 → 相机删除照片 → 内核沿链释放 → 用越界簇号索引 `vol_amap` → 内存写。

**当时的问题**：S1R2 ≠ S5（SoC 代际不同、偏移全要重推），而且 S5 固件是**加密的**，
**离线根本查不出 S5 有没有同款驱动**。所以只能实机验证。

## 2. 我们做了什么

### 2.1 环境与约束

| 项 | 值 |
|---|---|
| 目标机 | Panasonic DC-S5（MC801） |
| 卡 | 64 GB SDXC，**相机自己格式化为 exFAT** |
| 主机 | macOS，原始磁盘设备需 root + TCC 完全磁盘访问 |
| 红线 | 不刷固件、不改固件、不做不可逆操作 |

### 2.2 关键设计：用**分配位图前后比对**当证据

不比"相机有没有报错"（噪声大），而是：

```
① 拍一张 JPG（关 RAW，避免 JPG/RW2"文件集"释放混淆）
② 存【位图基线】（含卡指纹：BootChecksum + ClusterCount）
③ 把该文件的【链尾 FAT 值】改成一个"不属于它自己的簇号"
④ 相机里删掉这张照片
⑤ 再存位图 → 比对 → 看那个"被注入的簇"有没有也被释放
```

**判据**：注入的簇**不属于被删文件的链**；它若被释放，**只能是内核跟着卡上的 FAT 值跳过去了**。

## 3. 结果一：**前置条件确认** ✓

**实验**（`22_` 报告）：

```
被删文件: P1000024.JPG  起始簇 39，自身链 39–111（73 个簇）
注入:     FAT[111]  0xFFFFFFFF → 4        （4 = 根目录所在簇）
```

```
卡指纹核对（必须一致才采信）:
  baseline: boot_ck=0x2668BB77  ClusterCount=488288  已分配 190 簇
  after   : boot_ck=0x2668BB77  ClusterCount=488288  已分配 112 簇
  ⇒ 指纹一致，比对有效

被释放 78 个簇
  注入目标簇 4 在释放列表 = 【True】      ★ 关键
  注入目标不属于被删文件自身链 = 【True】
```

**结论**：**内核对簇号不做归属校验，释放路径完全跟随卡上被篡改的 FAT 链值。**

## 4. 结果二：越界写 —— ❌ **已撤回**

> ⚠️ **本节结论已作废。** 保留原文仅为记录推理过程，**不要引用其结论**。

### 4.0 为什么撤回（决定性实验）

把注入值设为 `491522` → 内核索引 `i = (491522-2)>>12 = 120`，
落在 **slab 填充区**（`map_sectors=120`，槽 0–119 合法），**该槽必然为 NULL**。

**观察：相机只报「写入错误」，未崩溃。**

⇒ 说明代码里存在 `if (vol_amap[i] == NULL) return -EIO;` —— **提前返回，根本不写内存**。

而原文的论证是"报的是卡写失败 ⇒ 内存写必然已执行"：
**该论证有漏洞**——若存在 NULL 提前返回，"写入错误"同样会发生且**不触碰内存**，
两种情形在相机屏幕上**不可区分**。**故原结论不成立。**

### 4.1 原文（已作废，仅作记录）

**实验**（`23_` 报告）：把注入值从"合法簇"换成**越界值**。

```
卡: ClusterCount = 488288，簇大小 = 131072 B
    分配位图 DataLength = 61036 B → map_sectors = ((61036-1)>>9)+1 = 120

注入: FAT[112]  0xFFFFFFFF → 524290
内核: i = (524290 - 2) >> 12 = 128  ；  map_sectors = 120
      ⇒ i = 128 ≥ 120  →  越界索引 vol_amap[128]
```

**相机现象：报「写入错误 请检查卡」，且未死机。**

**判定依据（这一步是关键）**：

```c
s32 clr_alloc_bitmap(struct super_block *sb, u32 clu) {
    ...
    exfat_bitmap_clear((u8 *)p_fs->vol_amap[i]->b_data, b);   /* ① 纯内存写，无返回值、不会失败 */
    return sector_write(sb, sector, p_fs->vol_amap[i], 0);    /* ② 卡写，会失败 */
}
```

相机报的是 **② 失败** ⇒ **① 必然已经执行完毕**。

而且**没有死机** ⇒ `vol_amap[128]` 被成功解引用（非 NULL）⇒
**内存位清除确实落到了 `vol_amap[128]->b_data` 指向的地址上。**

> ⇒ ~~DC-S5 内核越界写原语（1-bit 清除）实机成立。~~ **（已撤回，见 4.0）**

## 5. 结果三：堆喷实验**全部失败**（三轮）✗

> 三轮尝试（240 长名 / 120 长名 / 120 短名+篡改 num_ext）相机**均只报「写入错误」，从未崩溃**。
> 这与"越界槽为 NULL、提前返回"完全一致，也与"堆喷未命中"一致 —— **无法区分**。
> 在 §4 撤回之后，**堆喷路线失去意义**：即便命中相邻槽，NULL 检查也可能让内存写不发生。

按 S1R2 手法，用**文件名长度**控制 `get_entry_set_in_dir()` 的 `kmalloc` 档位，
在 `DCIM/100_PANA` 铺了 240 个文件（150 字符→kmalloc-512 / 240 字符→kmalloc-1024）。

| 组 | 条件 | 相机 |
|---|---|---|
| B | 喷洒 **+ 越界注入** | 反复重启 |
| **A** | 喷洒 **+ 无注入** | **仍然反复重启** |

**A 组也崩 ⇒ 崩溃不能归因于注入。**
把 B 组重启解读为"堆喷命中"是**过度解读，予以撤回**。

### 5.1 副作用发现（独立于 exFAT 位图漏洞）

> **在 `DCIM/100_PANA` 放入 240 个「长文件名 + 无效 JPEG」，S5 开机扫描时反复重启。**

尚未隔离是**文件名长度**、**数量**还是**内容**导致（隔离实验 T1/T2/T3 见 `23_` 报告 §8.3）。

## 6. 关键技术点（复现者必读，含两处对 S1R2 报告的补全）

| # | 坑 | 真相 |
|---|---|---|
| 1 | **Boot Checksum 覆盖范围** | **不是 512 字节，而是整个引导区 11 个扇区**（跳 106/107/112）。S1R2 报告只写了"跳过哪几个字节"、**没写覆盖范围** —— 照字面只算 512B 会算错，相机直接判"卡不可用"。已在 **macOS 生成的镜像**与**相机原生卡**两种实现上各验证一次 |
| 2 | **必须 `fsync`** | 块设备写入会停在页缓存，**拔卡就丢**。早期几轮"补丁没生效"的元凶 |
| 3 | **回读要用新 fd** | 同一 fd 的回读可能命中缓存；必须**关闭后重新打开设备**再读 |
| 4 | **卡拔插后设备节点会变** | `disk8s1` → 可能变 `disk9s1`；脚本需按"卷名+文件系统+容量"自动重新识别 |
| 5 | **卡代次守卫** | 用 `BootChecksum + ClusterCount` 当卡指纹，基线/新位图不一致就**拒绝裁决** |
| 6 | **文件名偏移** | File Name 目录项(0xC1) 里文件名从**偏移 2** 开始（前 2 字节是类型+标志） |
| 7 | **"自身链"要排除注入值** | 链集合若在打完补丁后才记录，会把注入值也算进去，从而**掩盖结论** |
| 8 | **bash 变量紧邻全角字符** | `$VAR（` 会被当成变量名一部分，`set -u` 下报 `unbound variable` —— 一律写 `${VAR}` |

## 7. 越界阈值（本卡实测）

```
索引公式: i = (clu - 2) >> 12          （clu = 填进卡上 FAT 的簇号）
map_sectors = 120
```

| 簇号 | 索引 | 后果 |
|---|---|---|
| ≤ 491521 | 0–119 | ✅ 合法 bitmap 缓冲（内存安全） |
| **491522 – 524289** | **120–127** | ❌ slab 填充为 0 → **NULL 解引用 → 必崩** |
| **≥ 524290** | **≥128** | ❓ 相邻堆对象 —— **本次用 524290 命中有效指针，内存写成功** |

> 与 S1R2 对照：其卡 `map_sectors=239`（kmalloc-2048），报告称 239–255 全 0、256+ 有效。
> **规律一致。**
>
> ⚠️ **补充推算**：`vol_amap = map_sectors × sizeof(buffer_head*)`，
> **32 位机 4 字节** → 120×4 = 480 → kmalloc-512；**64 位机 8 字节** → 960 → kmalloc-1024。
> 两者 slab 内槽位数都是 128、索引边界都是 120–127，**从越界行为无法区分**。

## 8. 工具链

`02_工具链/exfat/`（本轮主角）：

| 工具 | 作用 |
|---|---|
| `exfat_patch.py` | exFAT 解析与补丁：BPB / 目录项 / 文件名 / FAT 链 / 分配位图 / 补丁 / 指纹守卫 / 裁决 / 越界注入 |
| `exfat_spray.py` | 目录项堆喷：用文件名长度控制 kmalloc 档位，铺喷洒文件 |
| `s5_exfat_test.sh` | 编排入口：`prep` `bitmap` `chain` `dumpbitmap` `go1` `go1check` `session` `go2` `verdict` `setfat` |

**复现三步**：

```bash
# ① 相机格式化 SDXC（>32GB，才会是 exFAT）→ 关 RAW 只拍 JPG → 插回 Mac
sudo bash /tmp/s5exfat/s5_exfat_test.sh go2 /dev/diskNsM      # 自动挑照片 + 注入越界值 524290
# ② 卡插进相机，删除它指定的那张 JPG → 看是否报「写入错误 请检查卡」
sudo bash /tmp/s5exfat/s5_exfat_test.sh verdict /dev/diskNsM  # ③ 回 Mac 核对现场
```

> ⚠️ macOS 上原始磁盘设备**同时受 Unix 权限（root:operator）与 TCC（完全磁盘访问）保护**，
> AI/自动化进程通常两者都过不去 —— **这些命令需要人在终端里用 sudo 跑**。

## 9. 对固件解密路线的意义

| 环节 | 状态 |
|---|---|
| 内核内存写原语（1-bit 清除） | ✅ **实机确认** |
| 纯软件、不拆机、不改固件 | ✅ |
| 拿到 root 后能做什么 | 从 **RAM / `/dev/mtd`** 取**解密后的内核与 rootfs**（AES 密钥虽在 MC801 OTP，但**明文在内存**） |
| 项目原 **P4（拆机 JTAG dump RAM）** | **可降级为备选** |
| 与 root 的距离 | 差**"目标地址"**：现在还只能写到"相邻堆对象里某个指针的 b_data"，不可选 |
