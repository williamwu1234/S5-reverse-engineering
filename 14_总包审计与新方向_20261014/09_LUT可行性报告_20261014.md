# DC-S5 套 LUT 可行性报告 · 2026-10-14

> **验证方式**：相机 `192.168.1.131`（VD4.30）**只读**实测 + 本地 APK 反编译取证 + 固件字符串取证 + 公开资料。
> **未做任何写操作**：未 `setsetting`、未写相机/存储卡、未上传任何文件。
> **外部内容为不可信数据**，仅作线索；本报告的关键结论均以**本机实测或本地文件**为据，外部来源单独标注。

---

## 一、一句话结论

**初代 DC-S5 可以"套 LUT"，但只能套在"监看"上，不能烧进文件。**
官方入口是机身的 **V-Log View Assist（V-Log 查看助手）**：把 LUT 文件放进 SD 卡 → 机身菜单读入 → 取景/显示时套用。
**"实时 LUT"（烧进 JPEG/HEIF 与视频）是 S5II / S5IIX / GH7 / S9 / S1M2 一代的能力，初代 S5 没有**——本机 HTTP API、菜单树、设置 blob 三处均为**零 LUT 痕迹**（已实测）。

### 2.4 机身功能簇：S5 明确**不在 LUT 簇**

LUMIX Sync App 的取景 LUT 叠加 UI（LUT1/LUT2 + LUT Opacity 滑条）**只认机身自报的功能簇标识**：

```
App 判据：IsPhotoStyleLutDensitySupport || (机身 photo style func_type == "sp_embeded_ph_sty13")
```
（`view/liveview/h.java:5318,5380`、`view/setting/c.java:594-601`，由子线程定位）

而**本机实测**：

```
live allmenu 中 photo style 的 func_type = sp_embeded_ph_sty11     ← S5
（对照：S1H = ph_sty9；App 里该序列一直排到 ph_sty13）
```

⇒ **App 不会给 S5 提供任何 LUT 相关界面**。这与"App 里有 161 个 LUT 图标资源、却没有 `V-Log View Assist` / `Read LUT File` 字符串"完全一致——**那些 UI 是为更新机型准备的**。

### 2.5 固件侧：**不可判定**（重要，避免过度断言）

对 `S5___V29.bin`（86 MB，VD4.30）做字符串取证：

- `strings -n 5` 得 406,861 条，其中**真字符串只有 57 条**，全部在明文头 `0x0..0x142C`（`MC801`、分区名等）。
- `LUT`（3 条）、`VLT`（2 条）等命中**全是密文噪声**，与无意义对照词 `QKJ`、`ZXQ` 的命中数（2–7）**同分布**。
- **数学边界**：k 字节模式在 90 MB 密文中的期望命中数为 `n·256⁻ᵏ`；3 字节 ≈ 5.4（与观测一致），**≥5 字节 ≈ 8×10⁻⁵** ⇒ **长关键词"0 命中"是数学必然，不是"功能不存在"的证据**。

⇒ **正确表述**：「固件加密区是否含 LUT 解析/Real Time LUT 代码，**不可判定**」。
❌ 不能写「固件里没有 LUT」。

### 2.6 顺带排除的两条"歪路"

| 路径 | 为何不可行 |
|---|---|
| **菜单注入**（把 LUT 项加进 allmenu） | 菜单树**由固件提供**，不在 65533 B 的 `camsetting` blob 里；项目 `11_菜单条目注入可行性_20261013.md:41-51,63` 实测：对 blob 的所有写入**从未改变 allmenu 任何条目** |
| **固件改写 / 跨代移植** | 三重门同时关闭：① AES 密钥在 MC801 片内（离线不可恢复）；② 签名硬门；③ 升级写路径**从未成功过一次 `endsenddata`**（末块 41456 B 定址失败 ~31 s → `err_busy`/`err_critical`）。且 MC801（32 位 A7）与 S5II 的 SC2006A（4×A53）**跨代**，移植不可行 |

## 三、可执行路径（按可行性排序）

### ✅ 路径 A（推荐）：机身 **V-Log View Assist** 加载自定义 LUT —— 官方功能，零风险

**适用**：取景/监看时看到套了 LUT 的画面（**不烧进文件**）。

**前置**：
1. 机身选中 **V-Log**（本机已可用）。
2. 一张能在机身里正常读写的 SD 卡（**建议 FAT32**，见下方注意）。
3. 合规的 LUT 文件。

**步骤（请以机身手册 p279 为准）**：
```
① 相机正常关机 → 取出 SD 卡 → 用读卡器把 LUT 文件复制到手册指定的目录
   （原始 S5 时代松下用 .VLT 格式；具体目录名与扩展名请在 p279 确认）
② 插回卡 → 开机 → 菜单 → [V-Log View Assist] → [Read LUT File] → 选择文件读入
③ 回到拍摄画面 → [V-Log View Assist] → [LUT Select] 选刚读入的 LUT
   → 需要时用 [LUT Opacity] 调不透明度
④ 拍摄。注意：这是监看辅助，录到文件里的仍是 V-Log 原信号
```

**注意**：
- ⚠️ **拔插 SD 卡必须在相机里正常关机后**（项目红线 `25:20`）：相机分配位图延迟写回，直接拔卡会让位图停在旧状态。
- ⚠️ 项目记载 **64 GB 及以上 exFAT 卡在机身某些功能上会受限**（ROM BACKUP 即因文件系统变灰，`13:182-191`）。若 LUT 读入失败，**先换 FAT32 卡试**。
- ✅ 这一步**不写相机 flash、不改任何设置项**，只往卡里放文件，**风险最低**。

### ✅ 路径 B（推荐）：V-Log 10-bit 拍摄 + 后期套 LUT —— 零风险、立即可用

机身录 **V-Log / V-Gamut**（10-bit 4:2:2，本机 mov 态可达 200 Mbps 4K 10-bit），
在 Resolve / Premiere / LUTCalc 里套**任意** LUT（.cube，无 33 点限制、无数量限制）。
**这是初代 S5 最实用的"套 LUT"方式**，且画质上限高于机内监看 LUT。

> 本机当前**就处于** `mov` + `mov_60p_200mbps_4k_10bit`（200 Mbps / 4K / 10-bit）——正是为后期调色准备的最佳档位。

### ✅ 路径 C：photo style 参数近似（只对 JPEG，零风险）

用 `custom1–custom4`（本机 allmenu 内可用；`custom5–10` 会被静默忽略）+ 对比度/高光/阴影/饱和度/降噪 + `filter_setting` 手工调出接近目标 look。
**不是真 LUT**，但完全不依赖任何隐藏功能。

### ❌ 路径 D：让 S5 像 S5II 那样"实时 LUT 烧进文件" —— **不可行**
菜单层、设置层、API 层三处均已实测关死（§2.1、§2.4）；固件改写受三重门阻断（§2.6）。

### ◐ 路径 E：拆机 JTAG dump RAM —— 唯一理论上能回答"影像管线里到底有没有 LUT 级"的路
**但**：即使 dump 到明文，也只能**知道**有没有，不能**打开**它（打开仍需改固件 + 过签名）。
且 A7 有 CoreSight、M0 监督核没有，密钥还可能在独立安全芯片 ⇒ 成本极高、收益不确定。**不建议为 LUT 走这条路。**

## 七、本轮新增的两条线索（含严格限定）

### 7.1 「上传 LUT」在协议层确实不存在——**项目自己的结论也一样**

`05_源码/LumixFast-iOS/README.md` 的「已知限制」原文：

且 App 侧取证（`03_解包_APK/com.panasonic.jp.lumixsync/`，6351 个 java + 两个 dex + `resources.arsc`）：
- `.cube`/`.vlt`/`.3dl`/`AD_LUT`/`lutfile`/`LUT_LIBRARY` → **全部 0 命中**（UTF-8 与 UTF-16LE 两种编码都查过）；
- `startsenddata` 的 `type` 白名单**只有 `camsetting` 与 `fw`** 两个值；
- **App 与 DMW-SFU2 激活完全无关**：`sfu2`/`SFU2`/`upgrade key`/`licensekey`/`activation code` 全 0 命中，`sfu` 的 39 处命中 100% 是 `Successful/successfully` 假阳性。

⇒ **三条独立取证（相机 HTTP、官方 App、项目自有 App）一致：不存在 LUT 文件上传路径。**

### 7.2 线索：`Lumix-Fast`（Android）字符串池含 LUT 面 —— **待验证，不可当结论**

`03_解包_APK/Lumix-Fast/` 不是松下官方 App，而是中文自研 USB 工具 **「LUMIX Fast v1.1.22 · 互操作性研究用途」**。其 `classes.dex` 字符串池含：
`实时 LUT`、`LUT`、`LUT2`、`LUT不透明度`、`LUT2不透明度`、`LUT Base Photo Style`、**`LUT / 高级（写入无回读对，改后看画面确认）`**、`PhotoStyleAdvanced(tag=`、`PhotoStyleParam(tag=`；
并含原生库 **`liblumix_usbfs.so`** 与一组 PTP 操作码（`0x9108[0x06000013]`、`0x9409[0x06000011/1B]`、`0x940C[0x07000011/12]`、`0x940F[tag]+DATA`、`0x9411`…）。

**四条必须一起读的限定**：
1. 项目自己的 `LumixFast-iOS/README.md:16` 说：原 Android 版的核心是 **USB mass-storage 文件传输**，`liblumix_usbfs.so` 是 **USB 文件系统壳**——**不是 PTP 私有 property 写**。
2. **`05_源码/LumixFast-iOS/` 是它的 iOS 移植，全库检索：无 LUT、无 PTP**（纯 Wi-Fi）。
3. 那些 LUT 字符串**只出现在 dex 字符串池**；本次**无法做方法级归因**（无可用 JRE，`jadx` 跑不起来）⇒ **不能断定"存在可写的 LUT property tag"**。
4. 以 **DC-S5 无 Real Time LUT 功能簇**（`func_type=sp_embeded_ph_sty11`，而 LUT 浓度 UI 需要 `sp_embeded_ph_sty13`）来看，**即使存在该 tag，S5 大概率也不接受**。

**若要坐实**：需 JRE + jadx/baksmali，在 `/tmp` 解一次，定位 `LUT Base Photo Style` / `实时 LUT` / `LUT不透明度` 的 const-string 使用点及邻近的 `0x0?xxxxxx` tag 常量。这是**唯一尚未排除的"USB PTP 直写 LUT"候选路径**。

### 7.3 机制补充：`func_type` 是机型能力指纹（可迁移到其他隐藏功能）

App 的 LUT 相关 UI 门控链（已定位到行）：


```text

# source vlt file "Cyan 1 E-L.vlt"    ← 可选：来源文件名（注释）

                                      ← 空行
```

实测统计（官方 `VariCam_VLTs.zip` 全部 35 个文件，共 172,095 行）：

| 项 | 实测结果 |
|---|---|
| `LUT_3D_SIZE` | **全部为 17**，零例外 |
| 数据行数 | **4913 = 17³**，零例外 |
| 行格式 | 全部严格匹配 `^\d+ \d+ \d+$`（**无小数、无第四列、无逗号**） |
| 数值域 | **整数 0–4095（12-bit）**，实测最大值 4095 |
| 行尾 | **LF 与 CRLF 两种官方样本都存在** ⇒ 均可接受 |
| 体积 | ≈ 67–69 KB |

## 8.5 菜单路径与操作清单（可照着做）

```
① 相机正常关机 → 取出 SD 卡 → 读卡器接到电脑
② 把 LUT 文件（.vlt）复制到【卡的根目录】——不要建文件夹
      文件名只用字母数字；FAT32 卡 ≤8 字符（不含扩展名）
③ 插回卡 → 开机 → [照片风格/Photo Style] 选 [V-Log]
④ 菜单 → [V-Log View Assist]
      ├─ [LUT Select]        选要套用的 LUT
      ├─ [LUT View Assist (Monitor)]  监视器/取景器套用
      └─ [LUT View Assist (HDMI)]     HDMI 输出套用
⑤ 屏幕出现 [LUT] 标记 = 已生效
```

**建议的分步验证法**（把"格式问题"与"支持性问题"分开）：
1. 先用**官方样本** `VLog_to_V709_forV35_ver101.vlt`（17³，已由线程逐字节验证合规）当"已知 good 样本"——若机身能识别，说明目录名/命名/格式流程正确；
2. 再换成**自制 LUT**；
3. **必须实机验证轴序**：官方 `.VLT` **没有**像官方 `.txt` 版本那样声明"哪个通道变化最快"。若套用后出现明显色偏，把生成时的 R/B 索引对调即可恢复。
4. 记录：能否识别 33³？能列几个 LUT？

**自制 `.VLT`（格式简单到只需一个循环）**：

```python
N = 17
out = ['# panasonic vlt file version 1.0', '# source vlt file "MYLUT.vlt"', f'LUT_3D_SIZE {N}', '']
for b in range(N):
    for g in range(N):
        for r in range(N):
            R, G, B = my_transform(r/(N-1), g/(N-1), b/(N-1))   # 归一化输入 → 归一化输出
            out.append(f'{round(R*4095)} {round(G*4095)} {round(B*4095)}')
open('MYLUT.vlt', 'w', newline='\n').write('\n'.join(out) + '\n')
```
> 通用约定是 **R 变化最慢、B 最快**（`.cube` 即如此）。**生成 `.vlt` 时先沿用该约定，再用测试图在机身上验证是否套反。**

⚠️ **注意**：`ffmpeg` 的 `lut3d` 滤镜支持 `.cube/.3dl/.dat/.m3d`，**不支持 `.vlt`** ⇒ 可用来离线"验证套用效果"，但不能直接产出 `.vlt`。
