## 1. 一句话结论

**修正 `+0x200` 偏移、并用两组阳性对照证明「搜索确有检验力」之后，五个版本的 S5 固件对唯一

（表头 16/24/32B 滑窗、SHA 摘要派生、签名区、PTool 表、字符串常量、确定性填充，共 5240 个）
中，**没有任何一个是这些加密分区的 AES 密钥**。

这把权威文档 §1-2「仍站得住：密钥不在固件文件内」从**假阴性支撑**升级为**真阴性支撑**：
旧两次「0 命中」因 7 个脚本 off-by-0x200 对假设零检验力；本次是修正偏移后、在**已知有检验力**
的搜索下得到的负向证据，首次具限定意义。

判定口径：**◐ 离线希望渺茫（非终局）** 保持 —— 只能说「文件内派生候选」这一层被真阴性封死，
不等于证明密钥在不可导出处。

## 2. 任务来源

`01_唯一权威调用文档.md` §1-2 / §3-2 认定：两次「密钥搜索 0 命中」被当作终局证据不成立，
根因有二 ——（a）7 个密码脚本 off-by-0x200（`raw[doff:]` 应为 `raw[doff+0x200:]`）；（b）
「5240 密钥 0 命中」对假设零检验力（阳性对照 12/12 全假阴性）。修正动作即本节实验。

## 3. 方法（可复现）

单一真源 `upd_table.py`：`DATA_BASE=0x200`，`abs_off = doff + 0x200`，
`data(raw,e)=raw[e.abs_off : e.abs_off+e.size]`；反例对照臂显式走 `data_legacy_wrong()`（=旧的
`raw[doff:]`）。任何脚本不得手写 `raw[doff:]`。

1. **闸门（正确偏移自证）**：对 `type=2`（未加密）分区断言 `sha256(data)==记录内 SHA`。
   5 版固件全部 **7/7 PASS** ⇒ 说明「doff+0x200」是对的偏移，否则明文校验必失败。
2. **已知明文侦察**：扫描全部 `type=3`（加密）分区，找是否存在「可判定明文」——即全 0x00、
   或能与同族明文固件（G100 等）配对者，用作密钥搜索的 oracle。
3. **候选密钥集**（复刻 keyhunt/keyhunt2，共 **5240** 个）：
   - `hdr_windows` 622：表头区 16/24/32B 滑窗；
   - `ecdsa_windows` 0：`0x220..0x280` 签名疑似区是 64B 随机数据（低熵=0，每组 16B 含 0 字节被过滤）；
   - `digests` 20：目录/头 SHA 派生；
   - `ptool` 6：PTool 表方案 `key[i]=file[base+i*0x200+table[i]]`，base∈{0,0x200,0x400,0x800,0x1000,0x1400}；
   - `strings` 4：固件内字符串常量；
   - `pad` 4588：对 16/24/32B 的确定性填充派生。
4. **搜索矩阵**：`{CBC, ECB, CTR(nonce=IV[0:8],ctr=IV[8:16]), CTR(nonce=IV[0:8],ctr=0)} ×
   {record IV, zero IV, hdr IV} × {16,24,32}B`；先用 **前缀 256B** 判 oracle（2^-2048 假阳性），
   命中再用整分区 SHA-256 二次确认。
5. **对照组（★ 关键）**：
   - **阳性对照（合成样本）**：把 `TRUE_KEY=00112233445566778899aabbccddeeff` 种进合成表头，
     用同一段搜索代码跑 —— 验证「代码能捞回已知密钥」。
   - **真实容器灵敏度对照（最强）**：把 `ipu_data` 密文替换为 `AES-CBC(TRUE_KEY, 记录IV)` 加密的
     全零，并把 `TRUE_KEY` 种进**真实 V29 表头**（仅内存，不落盘），再跑同一段搜索。

## 4. 结果（实测）

### 4.1 闸门与 oracle

- 5 版固件 `type=2` 分区 **`sha256(data)==记录SHA` 全部 7/7 PASS**（V29/V24/V23/V20/V11）。
- 41 个 `type=3` 加密分区中，**唯一**有可判定明文者 = **`ipu_data`**（idx=33，size=0x40000，
  明文全 0x00）。其余加密分区无可判定明文 ⇒ 无第二个 oracle。

### 4.2 搜索（真固件）

| 固件 | 正确偏移臂 试解 / 命中 | 错误偏移臂 试解 / 命中 |
|---|---|---|
| V29 / V24 / V23 / V20 / V11（各） | 104,980 / **0** | 104,980 / **0** |

五版固件、两臂、共 **1,049,800** 次试解，**正确偏移臂唯一命中密钥数 = 0**。

### 4.3 对照组（证明搜索有检验力）

- **阳性对照（合成样本）**：`correct` 臂 **6 命中（含真密钥）**；`wrong` 臂 **0** ⇒ 正确偏移有检验力，
  且正确复现了「错误偏移 = 假阴性」。
- **真实容器灵敏度对照**：`correct` 臂 **3 命中（含真密钥）**；`wrong` 臂 **0** ⇒ 在**真实固件容器**上，
  只要密钥确实在候选集/表头里，本次搜索一定捞得回。**因此本节的 0 命中不是代码/候选来源问题。**

## 5. 关键结构发现（本轮实测）

- 文件前 `0x200` 是**明文 UPD wrapper 头**（magic `UPD\0`、chip `MC80 1`、版本、`0x56 0xec 0x00`
  总长、`c0aa738e` 校验）；**容器头在 `0x2A0`**（自身重复 `UPD\0…`），**表在 `0x2EC`**，条目 stride 92B。
- doff 绝对化实证：条目 `loader3  doff=0xbc00 size=0xc000` → 数据实存于 `0xbe00`；
  `program  doff=0x17c00 size=0xfe7000 abs=0x17e00` ✓ 与「+0x200」一致。
- 熵分布：`0x220..0x280`（疑似签名区）为 64B 随机数据，无可用低熵窗口（`ecdsa_windows=0`）。

   任何一个是这些加密分区的 AES 密钥。
2. **权威文档 §1-2「仍站得住：密钥不在固件文件内」升级为真阴性支撑**（原为假阴性支撑）。

   **「修正偏移后重跑 = 真阴性（有检验力）」**（实验 5）。
