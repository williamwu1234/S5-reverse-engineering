# BLE 身份注册 vs Wi-Fi accctrl 门：两者独立（2026-10-13）

> 回答"能否用电脑像 App 一样稳定地与相机通信"以及"BLE 注册是不是 Wi-Fi 授权的钥匙"。

---

## 0. 结论速览

| # | 结论 | 强度 |
|---|---|---|
| 1 | **局域网（station）方式完全可行且稳定**：Mac 不切网、不看门狗、不依赖手机 | ✓ 实测 |
| 2 | BLE 侧**身份注册成功**（写 `8D08A420` 返回成功） | ✓ 实测 |

| 5 | ⇒ **两道门互相独立**：BLE 凭据面敞开，Wi-Fi 控制面仍需授权 | ✓ 实测 |

## 1. 为什么要改用局域网（station）

连相机热点（SoftAP）这条路**极不稳定**，实测统计：

| 现象 | 出现次数 |
|---|---|
| `Failed to join network S5-70E253. Error: -3970` | 12+ 次（含射频重置后） |
| `-3906` | 3 次 |
| `Could not find network`（热点瞬间消失） | 4+ 次 |
| 成功关联 | 3 次（06:30 / 06:39 / 07:18） |

原因有三层：
1. 相机 SoftAP **单客户端**，手机或残留会话会挡住；
2. macOS 发现该网络**无互联网**时**自动回落到家网** → 探测全部超时；
3. 相机 SoftAP 本身时开时关（广播不稳定）。

**转机**：让相机作为 **station 连家庭路由器**，Mac 留在家里网——`192.168.1.131` 直接可达，
**无需任何网络切换**。项目前期（`persist.py`、配置块读写、47 个设置域审计）本来就是这么做的。

## 2. 本轮实测（局域网，全程不切网）

工具：`04_工具与脚本/campaign2/ble_lan_pair.swift`（编译产物 `ble_lan_pair`）

```
目标 IP=192.168.1.131  seed=020000025AD6  UUID=4D454930-0100-1000-8001-020000025AD6
编码自检 encodeString("ABC",0x9032782C) = d33b70d1

[BLE] 发现 S5-70E253 rssi=-49 → 已连接 → 枚举 41 特征
[BLE] 写身份 DLNA_UUID = 4d454930010010008001020000025ad6
      ← 写回调 8D08A420 err=成功                    ✅
[BLE] 写设备名 → BLE 断链（身份已写完）

[Wi-Fi 阶段]
基线 req_acc  → err_user_refused,S5-70E253,remote,encrypted
req_acc_g     → err_param            ← 无密钥
req_acc_e     → err_param            ← 用 key=0 编码后仍被拒
+0s 轮询      → ok_under_research,S5-70E253,remote,encrypted   （状态在跳）
getstate      → err_reject
getinfo capability → err_reject
getinfo lens  → err_reject
getsetting videoformat → err_reject
req_acc_can   → err_critical
```

**判读**：
- BLE 注册**确实成功了**（明文写入，无任何认证）。
- 但 Wi-Fi 侧基线就报 **`err_user_refused`** —— 相机认为"用户未同意"。
- 所有读端点仍是 **`err_reject`**，**门没有打开**。
- `req_acc_g` 在本机固件上**不存在**（`err_param`），因此 APK 里那条
  "encrypted → 用密钥编码 UUID/名字走 `req_acc_e`" 的路径**在这台机器上走不通**。

⇒ **BLE 注册 ≠ Wi-Fi 授权**。相机对 Wi-Fi 控制面的门是**独立**的，
需要**机身侧动作**（确认/进入"等待应用"状态），而不是靠 BLE 递身份。

## 3. 与既有结论的合并

| 面 | 结论 |
|---|---|
| **Wi-Fi 控制面**（`cam.cgi`） | 有独立访问控制门；陌生客户端拿不到控制（`err_user_refused` / `err_reject`）✅ |
| **BLE 凭据面** | **无认证**：可读出 Wi-Fi SSID/密码（见 19 号报告）❗ |
| **两者的关系** | **不连通** —— BLE 注册的身份打不开 Wi-Fi 门 |

19 号报告里"BLE 凭据是 Wi-Fi 大门的钥匙"这一推论，**仅在某些相机确实用热点密码作为唯一门槛时成立**；
对本机而言，**`cam.cgi` 还有一层独立于密码的访问控制**，所以那把"钥匙"开不了这道门。
（本机热点密码为空，因此该钥匙本来也无意义。）

## 4. 工程建议（后续一律照此做）

1. **相机保持 station 模式连家庭路由器**，Mac 留在家网 —— 稳定、可反复、不打断会话。
2. 只有**专门测试热点安全性**时才切到 SoftAP，并且必须在同一脚本里原子完成"切换→取证→切回"。
3. 连接被拒时的排查顺序：
   `networksetup -removepreferredwirelessnetwork`（清失效 profile）
   → 射频 off/on → 确认手机 Wi-Fi+蓝牙都关 → 最后才怀疑相机 AP 状态。
4. 后台任务一律用 `./s5ctl.sh start|stop|status` 管理，避免脚本失控。
