# 操作手册

## A. 准备

1. 保持稳定电量，停止录像；不要在相机访问卡、升级或联机冲突时测试。
2. 用相机 Wi-Fi 功能建立到电脑的局域网可达连接。USB 充电线不是本流程的数据通道。查到相机实际 IPv4，替换下面示例地址。
3. 在机身选择视频模式、普通 MP4；暂时保持已有 PAL／NTSC 系统频率，不为此实验改制式。
4. 准备 Python 3.9+。解压交付包，在其目录执行命令，不需要安装第三方 Python 库。

工程模式是否必要尚未完成对照；不在这里提供工程模式切换组合键。若现有连接要求常规配对，先按原厂流程配对，不发未经核对的 req_acc 初始化命令。

## B. 只读确认

S1H：

```sh
python3 programs/lumix_hidden_format.py inspect --ip 192.168.2.107 --model S1H
```

原始 S5：

```sh
python3 programs/lumix_hidden_format.py inspect --ip 192.168.2.107 --model S5
```

程序为每次调用创建独立 captures 目录，IP 不自动发现、不硬编码到程序。`inspection.json` 中：

- `enabled`：当前机型／上下文启用的值。
- `enabled_not_declared`：启用但未在完整菜单声明 setter 的候选。
- `blocked_by_known_S1H_anomaly`：暂不允许测试的异常候选。

“not declared”是两份所采菜单之间的差异，不保证厂商所有界面都隐藏此项，也不能称为全部隐藏规格。若 getter 不支持、camsetting 不可取得、机型不符或状态非待机，程序拒绝写入。

## C. 单项选择

S1H 已验证的高规格 MP4（LPCM）：

```sh
python3 programs/lumix_hidden_format.py activate --ip 192.168.2.107 --model S1H --token mp4ed_25p_400mbps_4k_10bit --write --accept-secondary-change
```

S5：从它自己的 `enabled` 里选一个 MP4／MP4ed token，替换下例占位文字，不照抄 S1H 目标：

```sh
python3 programs/lumix_hidden_format.py activate --ip 192.168.2.107 --model S5 --token 本机已启用的token --write --experimental-s5 --accept-secondary-change
```

只有当 S5 本机列出 `mp4ed_25p_400mbps_4k_10bit` 为可用时，才可将它当作一个候选。没有这个 token 就没有该档位的接口支持证据，不尝试凭空拼接值。

`--accept-secondary-change` 表示接受“后台各格式记忆项可能保留变化，通用恢复不保证全配置还原”的限制，不表示接受升级、崩溃测试或代码注入。

程序成功状态 `selected_not_recording_verified` 只代表选中成功。失败后会尝试恢复可见原值；若 `rollback_error` 不为空，停止测试并查看机身状态。未支持或超时不进行自动重试。

## D. 在机身核对

打开视频菜单 → 图像格式：

1. 看“录制文件格式”是否显示 MP4（LPCM）。
2. 看“视频图像区域”实际显示 FULL／S35／PIXEL。程序不改此字段，勿凭 token 判断画幅。
3. 打开“录制质量”，记录分辨率、帧率、采样／位深、ALL-I／Long GOP、码率、音频。
4. 格式选择器若空白，退出该弹框；这是受测 S1H 已知限制，不把空框当成正常新增选项。

S1H 历史实机此处显示 3840×2160／25.00p、422／10bit／ALL-I、400Mbps、LPCM、Full-frame。S5 请记录其实际显示，不能用 S1H 文案填结果。

## E. 实际录制与离线检查

用机身录像键录 2–10 秒，再按一次停止，确认红色录像标记消失。不要用 CGI 开录。复制卡上刚录的原文件，不发微信转码后的版本。

自行准备 FFmpeg／FFprobe 后：

```sh
python3 programs/verify_recording.py /完整路径/测试文件.MP4 --output media_check_01
```

查看 metadata.json 的视频和音频 stream，再看 result.json 和 full_decode.log。需要验证 ALL-I 时额外导出所有帧类型：

```sh
ffprobe -v error -select_streams v:0 -show_frames -show_entries frame=pict_type,key_frame -of json /完整路径/测试文件.MP4
```

检查全部解码帧，而非只看首帧。黑场适合码流属性核对，但不能证明视角、解析力、动态范围或持续热稳定性。包内历史样片也是黑场。

## F. 重启及“我的列表”实验

正常关机再开机，记录格式／质量是否保留。受测 S1H 已保留一次。S5 必须自己验证。

可选下一步：在“录制质量”中对选中条目按 Q“添加到列表”，确认“录制质量（我的列表）”是否出现。原厂 S1H 手册 p265 说明登记时包含格式、系统频率和区域；本研究未实测隐藏项添加及从 MOV 重入，所以不要预先宣称无电脑入口已经成功。若尝试，请先记录当前成功状态，再分别记录保存、重入、重启结果；不要远程猜 addlist 命令。

## G. 恢复与交付反馈

用本次 activate 产生的 restore_journal.json，替换路径和实际机型：

```sh
python3 programs/lumix_hidden_format.py restore --ip 192.168.2.107 --model S5 --journal captures/本次目录/restore_journal.json --write
```

确认 visible_settings_restored；再看 snapshot_matches_original。前者 true、后者 false 只说明可见值回来了，不能声称全配置恢复。snapshot 二进制始终不发送给相机。

向研究者返回：机型／机身固件／频率／工程状态、本机候选 token、写后读回、机身菜单截图、原始测试片散列和离线媒体结果、恢复核对结果。先去除 IP、个人名称和凭据；原始 CAMSET 私下保留，不公开上传整个 captures 文件夹。
