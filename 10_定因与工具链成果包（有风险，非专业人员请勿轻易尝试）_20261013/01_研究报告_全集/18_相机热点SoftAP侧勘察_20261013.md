## 1. 方法：为什么要"脚本原子完成"

Mac 一切到相机热点就与家庭网络断开，而 AI 会话依赖家庭网络。
所以整个「切换 → 取证 → 切回」必须由**后台脚本原子完成**，人不在场也不会把机器留在相机热点上。

工具：
- `04_工具与脚本/campaign2/wifi_ap_probe.sh` —— 编排（切换/取证/恢复 + 联网自检）
- `04_工具与脚本/campaign2/s5_ap_probe.py` —— 只读取证（第一轮）

```bash
cd 04_工具与脚本/campaign2
( nohup bash wifi_ap_probe.sh "$PWD/out/s5_ap" 45 >/dev/null 2>&1 & )
```

### 1.1 踩到的两个坑（复现者必读）

1. **macOS 没有 `setsid`**（Linux 专有）。`setsid nohup …` 会直接"命令未找到"，
   脚本静默不执行。正确写法：`( nohup bash script.sh args >/dev/null 2>&1 & )`。
2. **bash 变量紧邻全角字符会被吞**：`"$ORIG_GW）"` 中的 `）`（U+FF09，多字节）
   首字节被当作变量名的一部分 → `ORIG_GW<乱码>: unbound variable`，
   配合 `set -u` 直接让**恢复函数从未执行**（第一次实测正是这样，需人工切回）。
   **修法：一律写 `${ORIG_GW}`。**

## 2. 第一轮实测（成功）

### 2.1 接入与 DHCP

```
[ap] 已连 S5-XXXXXX  ip=192.168.54.10  gw=192.168.54.1
dhcp_message_type: ACK   server_identifier: 192.168.54.1
lease_time: 0xe10 (3600s)   subnet_mask: 255.255.255.0
```

### 2.2 `accctrl` 的加密标志（关键对照）

| 所在网络 | `accctrl&type=req_acc` 响应 |
|---|---|
| 相机热点（SoftAP） | `ok_under_research,S5-XXXXXX,remote,**open**` |
| 家庭局域网（station） | `ok_under_research,S5-XXXXXX,remote,**encrypted**` |

⇒ 末位字段就是**链路加密状态**，并且**与 Windows 侧 beacon 解析（`capability=0x0401`，
Privacy 位 = 0，无 RSN/WPA IE）完全吻合**：相机热点是**明文开放网络**。

### 2.3 访问控制门：开放热点 ≠ 开放控制面

在同一热点网络内，**未做任何 App/accctrl 握手**时：

| 端点 | 结果 |
|---|---|
| `getstate` | `err_critical` |
| `getinfo capability / allmenu / curmenu / lens` | `err_critical` |
| `getsetting videoformat / ntcs_pal` | `err_critical` |
| `camcmd playmode` / `camcmd recmode` | `err_critical` |
| `camctrl` | `err_critical` |
| `startsenddata&type=camsetting` | `err_critical` |
| **`accctrl&type=req_acc`** | ✅ `ok_under_research,S5-XXXXXX,remote,open` |

**要点**：
- 相机**要求访问控制握手**，裸 GET 取不到任何数据，也**发不出任何控制命令**。
- 这**修正**了 16 号报告里"读类端点不受限"的说法——那只在**家网（station）且会话已建立**时成立。
- 同时说明 HTTP 层**没有 CSRF token / Origin 校验**：带外部 `Referer`/`Origin`
  的请求照样被正常处理（只是被 accctrl 门挡下）。**门只有一道，就是 accctrl。**

### 2.4 端口面：热点模式多开两个服务

| 网络 | 开放端口 |
|---|---|
| 家庭局域网（station） | `80` |
| **相机热点（SoftAP）** | **`80`, `50001`, `60606`** |

`50001` 与 `60606` 是**家网侧完全不存在的服务**，属**新攻击面**，待第二轮识别。

## 4. 安全含义小结

1. **相机热点是明文开放网络** —— 覆盖范围内任何设备都能关联（Mac 已实证）。
2. **但关联不等于控制**：所有控制/读取端点都被 `accctrl` 门挡住，返回 `err_critical`。
3. **真正的门在 accctrl**：`req_acc` 携带 `value=<UUID>`（`4D454930-…` 族）与 `value2=<名字>`。
   项目既有记录提示 **`req_acc` 可能在机身上弹确认提示**，且相机端**只有一个"待批复"槽**。
   → **"未授权客户端能否完成 accctrl" 是决定安全等级的唯一问题**，正是第二轮的 §2 要回答的。
4. **热点模式额外开 `50001`/`60606`**，是家网侧没有的面，需单独评估。
